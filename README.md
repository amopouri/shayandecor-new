# شایان دکور — سیستم مدیریت محتوای فروشگاه فرش (PHP + MySQL)

این نسخه یک سیستم واقعی و کامل است: **Frontend + Backend + پایگاه‌دادهٔ MySQL + پنل مدیریت + ورود امن + آپلود تصویر واقعی**. هیچ بخشی روی `localStorage` یا فایل JSON کار نمی‌کند؛ همهٔ اطلاعات در MySQL ذخیره می‌شوند و پنل مدیریت مستقیماً با پایگاه‌داده کار می‌کند.

---

## ۱. نیازمندی‌های هاست

| مورد | حداقل نسخه |
|---|---|
| PHP | ۸٫۱ به بالا (۸٫۲ توصیه می‌شود) |
| MySQL / MariaDB | MySQL 8.x یا MariaDB معادل |
| افزونهٔ PHP: `pdo_mysql` | الزامی |
| افزونهٔ PHP: `mbstring` | الزامی |
| افزونهٔ PHP: `fileinfo` | الزامی |
| افزونهٔ PHP: `gd` | اختیاری (بدون آن آپلود تصویر کار می‌کند اما تصاویر بهینه‌سازی/تبدیل به WebP نمی‌شوند) |
| PHP Sessions | باید فعال باشد (در اکثر هاست‌ها پیش‌فرض است) |
| دسترسی نوشتن (Write) | روی پوشه‌های `config/` و `uploads/products`، `uploads/categories`، `uploads/site` |

تقریباً هر هاست اشتراکی با cPanel که PHP و MySQL دارد، این نیازمندی‌ها را پوشش می‌دهد.

---

## ۲. راهنمای نصب روی cPanel (قدم‌به‌قدم)

### مرحلهٔ ۱ — ساخت دیتابیس
۱. وارد cPanel شوید و به بخش **MySQL Databases** بروید.
۲. یک دیتابیس جدید بسازید (مثلاً `user_shayan`).
۳. یک User جدید بسازید و رمز عبور قوی برایش تعیین کنید.
۴. آن User را به دیتابیس اضافه کنید (Add User to Database) و دسترسی **ALL PRIVILEGES** را فعال کنید.
۵. نام دیتابیس، نام کاربری و رمز عبور را یادداشت کنید — در مرحلهٔ نصب لازم می‌شوند.

### مرحلهٔ ۲ — آپلود فایل‌ها
۱. به **File Manager** بروید و پوشهٔ `public_html` را باز کنید (یا زیرپوشهٔ دامنهٔ موردنظر).
۲. فایل ZIP تحویل‌داده‌شده را در همان‌جا Upload کنید.
۳. روی فایل ZIP کلیک راست کرده و **Extract** را بزنید.
۴. مطمئن شوید فایل‌ها مستقیماً داخل `public_html` هستند (نه داخل یک پوشهٔ اضافه مثل `public_html/shayandecor/`).

### مرحلهٔ ۳ — اجرای نصب‌کننده
۱. در مرورگر به آدرس زیر بروید:
   ```
   https://دامنه‌شما.com/install.php
   ```
۲. مراحل نصب را دنبال کنید:
   - **مرحلهٔ بررسی سرور**: نصب‌کننده نسخهٔ PHP، افزونه‌ها و دسترسی نوشتن پوشه‌ها را بررسی می‌کند.
   - **مرحلهٔ اتصال دیتابیس**: اطلاعات دیتابیسی که در مرحلهٔ ۱ ساختید را وارد کنید (Database Host معمولاً `localhost` است).
   - **مرحلهٔ ساخت مدیر**: یک نام کاربری و رمز عبور برای ورود به پنل مدیریت بسازید.
۳. پس از پایان، صفحهٔ موفقیت نمایش داده می‌شود و می‌توانید وارد `admin.html` شوید.

### مرحلهٔ ۴ — قفل کردن نصب‌کننده
بعد از نصب موفق، فایل `install.php` **خودکار قفل می‌شود** (با ساخت فایل `install_lock.php`) و اگر دوباره بازش کنید فقط پیام «قبلاً نصب شده» را می‌بینید. برای امنیت بیشتر، توصیه می‌شود بعد از نصب فایل `install.php` را کلاً از هاست حذف کنید.

## ۴. راهنمای ساخت دیتابیس به‌صورت دستی (در صورت عدم استفاده از install.php)

اگر ترجیح می‌دهید دیتابیس را دستی بسازید:
۱. در phpMyAdmin وارد دیتابیس خالی خود شوید.
۲. تب **Import** را بزنید و فایل `database.sql` را انتخاب کنید.
۳. Charset را روی `utf8mb4` بگذارید و Go را بزنید.
۴. فایل `config/config.sample.php` را کپی کرده و به `config/config.php` تغییر نام دهید؛ سپس مقادیر `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` را با اطلاعات واقعی جایگزین کنید.
۵. چون در این حالت هیچ حساب مدیری ساخته نمی‌شود، باید یک رکورد در جدول `users` بسازید. ساده‌ترین راه، اجرای `install.php` است (حتی اگر جداول را دستی ساخته‌اید، نصب‌کننده تشخیص می‌دهد و از شما تأیید بازسازی می‌خواهد یا می‌توانید مرحلهٔ SQL را رد کرده و فقط حساب مدیر بسازید).

## ۵. راهنمای آپلود تصویر محصولات

۱. در پنل مدیریت، به **محصولات** بروید و محصول موردنظر را باز کنید (یا ابتدا محصول جدید را یک‌بار ذخیره کنید).
۲. در بخش «تصاویر محصول»، روی مربع `+` کلیک کنید و یک یا چند عکس (JPG، PNG یا WEBP) انتخاب کنید.
۳. عکس اول به‌صورت خودکار «تصویر اصلی» می‌شود؛ با کلیک روی ★ روی هر عکس می‌توانید آن را به تصویر اصلی تغییر دهید.
۴. برای تغییر ترتیب، عکس‌ها را با موس بکشید و جابه‌جا کنید.
۵. برای حذف یک عکس، روی ✕ کلیک کنید.

حداکثر حجم هر تصویر ۵ مگابایت و حداکثر ۲۰ تصویر برای هر محصول است. اگر افزونهٔ GD روی هاست فعال باشد، تصاویر خودکار فشرده و به فرمت WebP تبدیل می‌شوند (کیفیت بهتر، حجم کمتر).

## ۶. راهنمای پشتیبان‌گیری (Backup)

در پنل مدیریت → **پشتیبان‌گیری**، روی «دانلود نسخهٔ پشتیبان کامل دیتابیس» کلیک کنید. یک فایل `.sql` شامل تمام محصولات، دسته‌بندی‌ها، تنظیمات و محتوای سایت دانلود می‌شود. این فایل را در جایی امن نگه دارید.

**نکتهٔ مهم:** این پشتیبان فقط دیتابیس را شامل می‌شود. تصاویر آپلودشده در پوشهٔ `uploads/` قرار دارند و باید جداگانه (مثلاً با FTP یا File Manager → Compress) پشتیبان‌گیری شوند.

برای بازگردانی: فایل SQL دانلودشده را در phpMyAdmin → Import وارد کنید (جداول قبلی را جایگزین می‌کند).

## ۹. نکات امنیتی

- رمز عبور مدیر با `password_hash()` (bcrypt) ذخیره می‌شود؛ هرگز به‌صورت متن ساده در دیتابیس نیست.
- تمام کوئری‌های SQL با PDO Prepared Statements نوشته شده‌اند (محافظت در برابر SQL Injection).
- هر درخواست تغییردهنده (POST) به یک **توکن CSRF** نیاز دارد که فقط بعد از ورود موفق صادر می‌شود.
- آپلود تصویر: پسوند فایل، نوع MIME واقعی (نه فقط نام فایل) و محتوای تصویر بررسی می‌شود؛ فایل‌های اجرایی (`.php` و مشابه) به‌طور کامل رد می‌شوند، حتی اگر با پسوند `.jpg` ارسال شده باشند.
- پوشهٔ `uploads/` دارای `.htaccess` است که اجرای هرگونه اسکریپت (PHP، CGI و…) را داخل آن مسدود می‌کند.
- فایل‌های `config/config.php` و `database.sql` از دسترسی مستقیم مرورگر مسدود شده‌اند (`.htaccess`).
- Session با تنظیمات امن (`HttpOnly`, `SameSite=Lax`, و روی HTTPS پرچم `Secure`) پیکربندی شده و بعد از ۲ ساعت عدم‌فعالیت منقضی می‌شود.
- تلاش‌های ناموفق ورود محدود می‌شوند: بعد از ۵ تلاش ناموفق از یک IP، ۱۵ دقیقه قفل اعمال می‌شود.

## ۱۰. وابستگی به افزونه‌های اختیاری هاست

| قابلیت | نیاز به افزونه | در صورت نبودن افزونه |
|---|---|---|
| بهینه‌سازی و تبدیل تصاویر به WebP | `GD` | آپلود همچنان کار می‌کند؛ فقط تصویر بدون تغییر اندازه/فرمت ذخیره می‌شود |
| تشخیص نوع واقعی فایل آپلودی | `fileinfo` | الزامی — بدون آن آپلود تصویر غیرفعال است |
| رشته‌های فارسی و UTF-8 | `mbstring` | الزامی — بدون آن متن فارسی به‌درستی پردازش نمی‌شود |

## ۱۱. اگر بعد از نصب سایت یا پنل بالا نیامد

- بررسی کنید فایل `config/config.php` ساخته شده باشد (در صورت نصب از طریق `install.php` باید خودکار ساخته شود).
- بررسی کنید افزونهٔ `pdo_mysql` روی هاست فعال باشد (از پشتیبانی هاست بپرسید).
- بررسی کنید نام دیتابیس/کاربری/رمز در `config/config.php` درست باشد.
- خطاهای PHP در فایل لاگ هاست (`error_log`) ثبت می‌شوند؛ برای عیب‌یابی می‌توانید آن را بررسی کنید (کاربر نهایی خطای خام PHP نمی‌بیند، فقط پیام JSON استاندارد).

## ۱۲. به‌روزرسانی قالب‌ها (index.html / admin.html / product.html) و پاک‌سازی محصولات

این بخش برای زمانی است که نسخهٔ جدید سه فایل `index.html`، `admin.html` و `product.html` را دریافت کرده‌اید و می‌خواهید محصولات تستی را پاک کرده و از صفر با عکس واقعی شروع کنید.

### الف) چطور قالب‌های جدید را جایگزین کنم

۱. سه فایل جدید را که دریافت کرده‌اید کنار هم روی کامپیوترتان قرار دهید: `index.html`، `admin.html`، `product.html`.
۲. هیچ فایل دیگری (دیتابیس، api/، config/، uploads/) را دست نزنید — این سه فایل کاملاً مستقل از بقیهٔ پروژه کار می‌کنند و فقط ظاهر و تجربهٔ کاربری را عوض می‌کنند، نه داده‌ها را.

### ب) چطور روی هاست آپلود کنم

۱. وارد **File Manager** هاست شوید (یا با FTP مثل FileZilla وصل شوید).
۲. به پوشهٔ `public_html` (یا هر پوشه‌ای که پروژه در آن نصب است) بروید.
۳. فایل `index.html` موجود را حذف کنید و فایل جدید را آپلود کنید.
۴. همین کار را برای `admin.html` تکرار کنید.
۵. همین کار را برای `product.html` تکرار کنید.
۶. فایل جدید `clear-products.php` را هم در همان پوشه (کنار `install.php`) آپلود کنید.

نیازی به اجرای دوبارهٔ `install.php` و نیازی به دست‌زدن به دیتابیس نیست؛ این فقط جایگزینی سه فایل HTML و افزودن یک فایل PHP است.

### ج) چطور اسکریپت پاک‌سازی محصولات را اجرا کنم

۱. ابتدا از طریق `admin.html` با نام کاربری و رمز خودتان وارد پنل مدیریت شوید (این مرحله اجباری است؛ بدون ورود، اسکریپت اجرا نمی‌شود).
۲. در همان تب مرورگر، به آدرس زیر بروید:
   ```
   https://دامنه‌شما.com/clear-products.php
   ```
۳. یک صفحهٔ هشدار می‌بینید که توضیح می‌دهد چه چیزی حذف می‌شود (محصولات، تصاویر محصولات) و چه چیزی حذف **نمی‌شود** (دسته‌بندی‌ها، تنظیمات، حساب ادمین).
۴. تیک «متوجه‌ام و می‌خواهم ادامه دهم» را بزنید.
۵. در کادر متنی، دقیقاً کلمهٔ `DELETE` را تایپ کنید (با حروف بزرگ انگلیسی).
۶. دکمهٔ «پاک‌سازی همهٔ محصولات» فعال می‌شود؛ روی آن کلیک کنید.
۷. صفحهٔ نتیجه تعداد محصولات، تصاویر و فایل‌های حذف‌شده را نشان می‌دهد.
۸. **بلافاصله بعد از اجرای موفق**، فایل `clear-products.php` را از روی هاست حذف کنید (از File Manager) تا کسی دیگر نتواند دوباره اجرایش کند.

بعد از این مرحله، می‌توانید از پنل مدیریت → محصولات → «افزودن محصول»، محصولات واقعی را با عکس‌های واقعی اضافه کنید.

### د) چطور بعد از آپلود سایت و پنل را تست کنم

۱. سایت اصلی را باز کنید: `https://دامنه‌شما.com/index.html` — باید بدون خطا بالا بیاید (اگر محصولی نمانده، بخش‌های محصول خالی نشان داده می‌شوند، این طبیعی است).
۲. وارد `admin.html` شوید و چک کنید داشبورد بالا می‌آید و آمار (هرچند صفر) نمایش داده می‌شود.
۳. یک محصول تستی با یک عکس واقعی اضافه کنید و مطمئن شوید ذخیره می‌شود و روی `index.html` نمایش داده می‌شود.
۴. روی همان محصول در سایت کلیک کنید و مطمئن شوید به `product.html?id=...` با اطلاعات درست می‌رود.
۵. در پنل، دسته‌بندی‌ها، نظرات، سوالات متداول و تنظیمات سایت را چک کنید که دست‌نخورده و سالم مانده‌اند.

### ه) اگر خطا داد چه کار کنم

| مشکل | راه‌حل |
|---|---|
| صفحهٔ `clear-products.php` می‌گوید «دسترسی غیرمجاز» | باید اول در `admin.html` در همان مرورگر لاگین کرده باشید؛ لاگین کنید و دوباره صفحه را باز کنید |
| دکمهٔ پاک‌سازی غیرفعال می‌ماند | باید هم تیک را بزنید و هم دقیقاً کلمهٔ `DELETE` (بزرگ، انگلیسی) را در کادر بنویسید |
| بعد از جایگزینی فایل‌ها سایت سفید/خراب شد | مطمئن شوید فایل‌ها را کامل و بدون خرابی آپلود کرده‌اید (حجم فایل را با فایل اصلی مقایسه کنید)؛ دوباره آپلود کنید |
| محصولات در پنل نمایش داده نمی‌شوند ولی حذفشان نکرده‌اید | صفحه را Refresh کنید؛ اگر باز هم نبود، Console مرورگر (F12) را باز کنید و پیام خطا را بررسی کنید |

## ۱۳. یادآوری مهم

اگر بعداً پروژه را روی هاست دیگری منتقل می‌کنید، از بخش «پشتیبان‌گیری» یک نسخهٔ کامل SQL بگیرید و پوشهٔ `uploads/` را هم جداگانه کپی کنید؛ سپس در هاست جدید همان مراحل نصب را با فایل SQL خودتان (به‌جای `database.sql` پیش‌فرض) تکرار کنید.
